# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The public website for The Things Network New York (https://thethings.nyc), a 501(c)(3) deploying public LoRaWAN networks. A React 19 + TypeScript single-page app built with Vite 7 and Tailwind CSS 4 (via the `@tailwindcss/vite` plugin; there is no tailwind.config file).

## Commands

- `npm install` — install dependencies (Node 18+)
- `npm run dev` — dev server at http://localhost:5173
- `npm run build` — `tsc -b && vite build`; writes to `docs/` (not `dist/`)
- `npm run lint` — ESLint (flat config in `eslint.config.js`)
- `npm run preview` — serve the built site

There are no tests.

## Deployment

GitHub Pages serves the committed `docs/` directory on `main`. To deploy: run `npm run build`, commit the changed `docs/` output, and push (usually via a PR to `main`). `vite.config.ts` sets `outDir: "docs"` with `emptyOutDir: true`; the custom-domain `CNAME` file lives in `public/` and is copied into `docs/` on each build.

The `npm run deploy` script (`gh-pages -d dist`) is stale: the build writes to `docs/`, not `dist/`. Don't use it.

## Architecture

Routing uses `HashRouter` (URLs like `/#/stories`), which avoids needing a 404 fallback on GitHub Pages. All routes are declared in `src/main.tsx`; `src/App.tsx` is the layout shell (Header, `<Outlet/>`, Footer).

Content is data-driven, not CMS-driven, except the blog:

- **Stories**: metadata in `src/data/stories.ts` (the `Story` type); long-form bodies are markdown files in `src/content/stories/` with front matter, loaded eagerly in `src/pages/StoryDetail.tsx` via `import.meta.glob` and matched by the story's `mdPath`. A story without `mdPath` renders from its metadata alone.
- **Projects**: `src/data/projects.ts` exports `activeProjects` and related arrays rendered on the home page.
- **Repos**: `src/data/repos.json`, rendered by `src/pages/Repos.tsx`.
- **Teardowns**: photo galleries of LoRaWAN hardware. `src/data/teardowns.json` is generated by `uv run scripts/import-teardown-photos.py <source-dir>`, which resizes photos into `public/images/teardowns/<slug>/{full,display,thumb}/` and strips GPS EXIF (full-res copies keep their pixels and capture dates). Without `--merge` the source directory must hold a device's complete photo set; with `--merge` it adds or replaces only the photos supplied. Photo `caption` and device `description` fields in the JSON are hand-edited and survive re-import; never regenerate the JSON by hand. Pages: `src/pages/Teardowns.tsx`, `src/pages/TeardownDetail.tsx`, lightbox in `src/components/Lightbox.tsx`.
- **Blog**: `src/pages/Blog.tsx` reads and writes the `blogs` collection in Firestore (client config in `src/firebase.ts`), with an in-page markdown editor (`@uiw/react-md-editor`). Access control lives in Firestore rules, not in this repo.

Analytics: Mixpanel is initialized in `src/main.tsx` with autocapture and session recording.

Images and videos go in `public/images/` and `public/videos/`; data files reference them with paths relative to the site root (e.g. `images/stories/foo.jpg`, no leading slash, since the app is served with `base: "/"` under a hash router).

To add a story: add an entry to `src/data/stories.ts`, put the cover image in `public/images/stories/`, and (optionally) add a markdown file in `src/content/stories/` and set `mdPath` to its `src/...` path. Draft entries for planned stories are in `notes/success-stories.md`.

## Outside links

- **Donate**: both Donate links in `src/components/Header.tsx` (desktop nav and mobile menu) point to the TTN NY Zeffy donation form. Use only TTN NY's own form, never the Zeffy page for WestLight, the fiscal-sponsorship client.
- **Mailing list**: the Subscribe button (`src/components/GetInvolved.tsx`, URL passed from `src/components/Home.tsx`) opens Mailchimp's hosted signup form. The audience uses double opt-in, and the old embedded form was deleted after it filled the list with bot signups. A move of the list to Zeffy is planned; that move replaces this link.

## Notes and drafts

`doc/posts/` holds social-media text drafted for hand posting (Mastodon, Meetup, Slack), one file per announcement, named `<date>-<slug>.md`. `notes/` holds planning notes. Neither directory is part of the build.

This repo is public. Commit only what could appear on the website. People's names taken from Slack, private correspondence, money details from private mail, open questions, and local paths go in a working file outside git; see local memory for where that file lives on this machine.
